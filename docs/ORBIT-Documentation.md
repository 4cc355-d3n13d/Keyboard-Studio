# ORBIT — полная документация

Редакция от 30 октября 2026 года, Europe/Moscow. Документация описывает фактическую реализацию ORBIT Music Keyboard Studio 2.0.0 с проектами формата version 1. Исходный commit: **6550ce0988f9f51ea24905cb374491a3e7b3405d**.

## Что сохранено

Это самостоятельный комплект: руководство пользователя, справочник тембров, звукового движка и эффектов, все MCP-команды с точными схемами, форматы данных, архитектура, сборка, публикация, диагностика и примеры. Данные каталогов и схем извлечены из текущего кода. Факты о проверках отделены от рекомендаций для будущих изменений.

Удобнее всего открыть **ORBIT-Documentation.html**: все главы находятся в одном файле, есть поиск и печать. Markdown-файлы пригодны для редактирования. `reference/` содержит машиночитаемые схемы, параметры и образцы. `examples/` — готовые запросы и локальный сервер для разработки. `source/orbit-mcp-source.zip` — архив исходников этой редакции.

## Быстрый старт музыканта

1. Откройте [веб-студию](https://orbit-keyboard-studio-29oct.druidbeat.chatgpt.site/).
2. Нажмите **Start Audio**. Без запуска браузерного аудиоконтекста удалённая команда не включает звук.
3. Выберите инструмент, нажмите клавиши или пэды. **Play** запускает секвенсор.
4. Для полного сохранения нажмите **Сохранить**: JSON включает настройки, ноты и загруженные аудиосэмплы.
5. Для готового звука используйте **Экспорт → WAV**, для нот — **MIDI**.

Автономный `music-keyboard-studio.html` работает без сети. Удалённый MCP управляет подключённой веб-студией; отдельная вкладка `file://` не является её сессией.

## Быстрый старт управления из чата

1. Подключите личный плагин **ORBIT — Music Keyboard Studio** в поддерживаемом клиенте. В этой беседе команды уже были доступны и проверены.
2. В веб-студии дождитесь **MCP ● подключён**.
3. Нажмите **Start Audio**, затем напишите: «Выбери арфу и сыграй C–E–G».
4. Если открыто несколько веб-студий, сначала вызовите `orbit_list_sessions` и выберите `session_id`.

MCP endpoint: `https://orbit-keyboard-studio-29oct.druidbeat.chatgpt.site/mcp`. Этот же URL используется как OAuth resource. Один адрес сам по себе не заменяет авторизацию клиента.

## Граница документации

ORBIT — браузерная студия с одним выбранным мелодическим тембром, четырьмя микшерными каналами и синтезированными барабанами. Она не реализует полноценную многодорожечную DAW, VST-хост, серверный рендер или постоянный облачный архив проектов. Доступные функции и ограничения ниже относятся именно к сохранённой версии.

# Руководство пользователя

## Открытие, звук и сохранение

Веб-версия загружает студию с Sites и может подключаться к MCP. Автономная версия — один HTML со встроенным Tone.js; после скачивания интернет для игры не нужен. Проекты между этими версиями переносятся через JSON. Их браузерные хранилища могут быть разными.

Первый запуск звука требует нажатия **Start Audio**. Игра мышью или физической клавиатурой также может вызвать локальное включение аудио, но для предсказуемого управления через чат сначала нажмите отдельную кнопку. После перезагрузки аудиоконтекст создаётся заново. Если звука нет, проверьте кнопку Audio ON, системный выход, Mute и громкости.

**Сохранить** скачивает `orbit-session.json`. **Открыть** загружает JSON с диска и заменяет проект в текущей вкладке. Автосохранение действует с задержкой около 450 мс после изменений, содержит метаданные проекта и названия сэмплов, но не их аудиоданные. Значок «Сохранено на устройстве» не означает, что аудиосэмплы надёжно сохранены. Для них нужен полный JSON.

## Верхняя панель и транспорт

| Элемент | Поведение |
|---|---|
| Play / Pause | Запуск или пауза Tone.Transport; при паузе звучащие голоса отпускаются |
| Stop | Остановка, завершение записи, сброс позиции и арпеджиатора, снятие нот |
| Record | Начало или завершение записи исполнения в Piano Roll; старт записи запускает транспорт |
| BPM | Темп 40–240 четвертей в минуту; исходное значение 118 |
| Позиция | Такт : доля : шестнадцатая; размер фиксирован 4/4 |
| Loop | Повтор текущих 16 или 32 шагов |
| Click | Метроном по четвертям; первая доля такта звучит выше |
| Start Audio | Разрешение и запуск локального аудиодвижка |
| Экспорт | WAV одного цикла с хвостом или MIDI с нотами и ударными |

Пауза и Stop отличаются: пауза сохраняет позицию транспорта, Stop возвращает его к началу. Пробел использует переключение Play/Stop; это не то же самое, что кнопка Pause.

## Микшер и тональность

На широком экране микшер находится слева; на узком открывается кнопкой в заголовке. Четыре канала: **Инструмент** — живые клавиши, пэды с нотами и отдельный голос MCP; **Drum rack** — синтезированные барабаны и сэмплы; **Мелодия** — секвенсор и записанные мелодические события; **Master** — общий уровень. Громкости 0–100, кнопка M отключает канал. Сэмплы используют канал Drum rack, отдельного фейдера каждому пэду нет.

Выберите тонику C…B и гамму: Minor, Major, Dorian, Pentatonic или Chromatic. Pentatonic в коде — минорная пентатоника. **Scale Lock** приводит живые ноты к допустимым ступеням; при одинаковом расстоянии выбирает нижнюю ноту. Ранее записанные события Piano Roll воспроизводят сохранённые MIDI-ноты напрямую, а мелодическая строка секвенсора применяет Scale Lock при проигрывании.

Блок «Идея для трека» создаёт мелодический и барабанный паттерн в выбранной тональности. Доступны House, Techno, Trance, Ambient, Synthwave и Lo-fi. Это заданные последовательности ступеней и ритмический шаблон, а не вызов генеративной модели. House, Trance и Synthwave используют одинаковую последовательность ступеней в этой версии.

## Выбор тембра и избранное

Список сгруппирован по категориям. Номер рядом с названием показывает 1–36, а MCP использует ID 0–35. Например, Concert Harp отображается как 25 / 36, её API ID — 24.

Звезда добавляет текущий инструмент в раздел «★ Избранное». Избранное хранится отдельно от проекта в предпочтениях браузера. Его можно менять через MCP `favorite`, но полный JSON проекта не является резервной копией избранного.

При переключении тембра загружаются его стандартные ADSR, фильтр, громкость и панорама. Настройки общей цепи эффектов сохраняются. Quick Cutoff меняет фильтр инструмента, Space — долю Reverb. Для возврата начальных параметров текущего пресета есть Reset во вкладке «Звук».

## Клавиатура

Клавиши поддерживают мышь, касания и несколько одновременных указателей. Можно вести указатель по клавишам, пока он нажат. Z/X переключают начальную октаву 1–6, Zoom показывает 2–4 октавы, Velocity задаёт силу новых нот 0.1–1.

| Физическая клавиша | Полутон от начала текущей октавы |
|---|---|
| A | 0: C |
| W | 1: C# |
| S | 2: D |
| E | 3: D# |
| D | 4: E |
| F | 5: F |
| T | 6: F# |
| G | 7: G |
| Y | 8: G# |
| H | 9: A |
| U | 10: A# |
| J | 11: B |
| K | 12: C следующей октавы |
| O | 13: C# следующей октавы |
| L | 14: D следующей октавы |
| P | 15: D# следующей октавы |
| ; | 16: E следующей октавы |
| ' | 17: F следующей октавы |
| ] | 18: F# следующей октавы |

Соответствие основано на `KeyboardEvent.code`, то есть физических позициях клавиш. Когда фокус находится в input/select/textarea или при нажатых Ctrl/Meta/Alt, музыкальные сочетания обычно не обрабатываются. Автоповтор нажатия не создаёт повторных атак.

**Shift** временно включает Sustain. Кнопка Sustain фиксирует удержание; после отпускания Shift возвращается состояние этой кнопки. Pitch bend меняет detune, сбрасывается при отпускании, потере фокуса или Stop. Modulation добавляет вибрато к живому тембру. При уходе со вкладки или потере фокуса сбрасываются удерживаемые ноты и пэды: это защита от зависшего звука.

## Performance Pads

16 пэдов доступны в четырёх режимах. Цифры 1–8 запускают первые восемь пэдов; остальные доступны указателем.

| Режим | Что играет |
|---|---|
| Аккорды | Трезвучия по ступеням текущей гаммы либо выбранный тип от корня ступени |
| Drums | 16 названий/вариантов на базе шести синтезаторов ударных |
| Samples | Локальный аудиофайл выбранного пэда или встроенный синтезированный буфер |
| Гамма | Последовательные ступени текущей гаммы |

Типы аккордов: «В тональности» (`auto`), Major, Minor, Seventh, Sus2, Sus4, Diminished. Seventh здесь строится как [0,4,7,10], то есть доминантсептаккорд. Для режима auto используются ступени i, i+2, i+4 выбранной гаммы.

Для загрузки сэмпла переключитесь в Samples, нажмите нужный пэд, затем кнопку загрузки. Выбирайте аудиофайл до 8 000 000 байт; WAV/MP3 поддерживаются, если браузер умеет декодировать конкретный файл. One-shot играет весь буфер, Gate — пока пэд удерживается, Loop повторяется до отпускания. Пользовательское аудио включается в JSON при сохранении. Встроенные звуки синтезируются на месте.

## Секвенсор

Строки: Мелодия, Kick, Snare, Hi-hat, Clap. 16 шагов — один такт 4/4, 32 — два такта. Каждый шаг — шестнадцатая. Клик включает/выключает ячейку. В мелодической строке Shift+клик или правый клик назначают выбранную в списке ноту и включают шаг.

Кнопка «Мелодия» случайно заполняет мелодическую строку нотами выбранной гаммы; барабаны сохраняются. «Очистить» очищает секвенсор, но не Piano Roll. Humanize слегка меняет velocity и добавляет до 12 мс задержки в реальном проигрывании секвенсора. Swing задаётся отдельно. Изменение длины паттерна останавливает транспорт.

Undo/Redo хранит до 40 состояний паттерна, записанных событий и длины. Он не откатывает все настройки студии, громкости или смену инструмента. Сочетания: ⌘/Ctrl+Z и ⌘/Ctrl+Shift+Z.

## Арпеджиатор

Arp превращает удерживаемые живые ноты в последовательность. Режимы: Up, Down, Up/Down, Random, Played order. Частоты 1/4, 1/8, 1/16, 1/32; диапазон 1–3 октавы; Gate 0.1–0.95 задаёт долю длительности шага. Арпеджиатор использует транспорт и запускает его при локальной игре, если это необходимо.

MCP `orbit_play_notes` использует отдельный remote-голос и играет запрошенный аккорд напрямую. Настройка Arp через MCP не превращает такой однократный аккорд в длительное удержание для арпеджиатора.

## Запись и Piano Roll

Нажмите Record, сыграйте, затем Stop или выключите Record. Записываются ноты, ударные и сэмплы; длительность живой ноты учитывает отпускание и Sustain. Пока идёт запись, воспроизведение ранее записанных событий подавляется, а секвенсор может продолжать играть.

В Piano Roll перетаскивайте ноту по времени и высоте. Правый край меняет длину. Двойной клик по пустому месту добавляет ноту, правый клик по событию удаляет его. Перетаскивание использует сетку в четверть шага; Quantize округляет начало и длину к выбранным 1/16, 1/8 или 1/4. «Очистить запись» удаляет события Piano Roll и не очищает секвенсор.

Секвенсор и Piano Roll при проигрывании складываются. При совпадающих нотах можно услышать наложение, а не замену одной партии другой.

## Эффекты, XY и визуализация

Во вкладке «Эффекты» доступны восемь эффектов с переключателями и двумя параметрами. XY-площадка одновременно меняет Cutoff и/или Mix Reverb/Delay/Distortion; оси выбираются в списках. Она доступна указателем и стрелками. Изменение XY может включать соответствующий эффект. Подробные значения — в справочнике звука.

Визуализация: Oscilloscope, Spectrum, Neon Particles, Pulsing Geometry. Это отображение локального мастер-сигнала, не отдельный генератор. Она обновляется примерно до 30 кадров/с, прекращает рисование в скрытой вкладке, ограничивает плотность canvas значением 2.

## Playground

Learn to Play предлагает последовательность подсвеченных нот. Rhythm Challenge просит 16 попаданий по Kick возле метронома; допустимое отклонение около 160 мс. Chord Challenge — четыре заданных аккорда. Beat Builder последовательно просит Kick, Snare, Hi-hat, бас ниже C4 и мелодию C4 или выше.

За верное действие начисляется 10 + min(серия,10) очков; ошибка сбрасывает серию. Отображаются точность, очки, серия и достижения. Запуск упражнений может менять октаву, режим пэдов, метроном и транспорт. «Свободная игра» прекращает упражнение, сохраняя возможность играть.

# Инструменты и звук

## Общие принципы

В студии 36 синтезированных тембров. Они создаются в браузере; названия Grand Piano, Flute или Guitar обозначают характер синтеза, а не использование записей реальных инструментов. Внешние банки сэмплов и платные звуковые библиотеки для этих пресетов не нужны. Выбран один текущий тембр, общий для живой игры, мелодии секвенсора и remote-голоса MCP.

MIDI-нота 60 = C4, 69 = A4 = 440 Hz. Частота вычисляется как `440 * 2 ** ((note - 69) / 12)`. Все API ID начинаются с нуля; номер на экране на единицу больше. Нумерация General MIDI в справочниках иногда начинается с 1; сохранённое значение program в ORBIT — байт 0–127.

## Типы синтеза

| voice в пресете | Реализация и характер |
|---|---|
| Synth | Tone.Synth внутри Tone.PolySynth; обычные, fat и custom-осцилляторы |
| FM | Tone.FMSynth; harmonicity, modulationIndex и отдельная огибающая модуляции |
| AM | Tone.AMSynth; амплитудная модуляция, включая fat saw и квадратный модулятор |
| Mono | Tone.MonoSynth внутри Tone.PolySynth: резонансный фильтр с огибающей; название класса не ограничивает весь инструмент одним голосом |
| Membrane | Tone.MembraneSynth; падение высоты и амплитудная огибающая для 808 |
| String | Собственный StringSynth на Web Audio с моделью щипковой струны |

Обычные PolySynth и StringSynth ограничены 32 голосами на экземпляр. Живое исполнение, секвенсор и MCP имеют отдельные экземпляры, поэтому удалённый аккорд не забирает удерживаемые клавиатурные голоса.

StringSynth использует Karplus–Strong: шумовое возбуждение, дробную задержку, затухание и фильтрацию обратной связи. Частота кэшируется с четырьмя знаками после запятой; на экземпляр хранится до 12 буферов. Длина затухания зависит от Decay, Sustain и параметра ringing, ограничивается 0.2–8 с до расчёта буфера. Для ситара и muted guitar добавлена нелинейная окраска buzz. Harpsichord имеет нижний порог velocity 0.7. Полные параметры каждого пресета сохранены в `reference/instruments.json`.

Sync Lead использует вычисленный спектр синхронизированной пилы: 32 гармоники из 1024 отсчётов. Это статическое спектральное приближение выбранного отношения частот, а не отдельный непрерывно управляемый hard-sync осциллятор.

## Параметры звука

| Параметр | Диапазон | Единица и смысл |
|---|---|---|
| attack | 0.001–2 | секунды нарастания |
| decay | 0.01–3 | секунды спада после атаки |
| sustain | 0–1 | относительный удерживаемый уровень |
| release | 0.03–5 | секунды отпускания |
| cutoff | 100–16000 | Hz низкочастотного фильтра инструмента |
| resonance | 0.1–12 | Q фильтра |
| volume | −30–0 | dB тембра до микшера |
| pan | −1–1 | −1 слева, 0 центр, 1 справа |

Быстрый Cutoff использует логарифмическое преобразование `100 * 160 ** (percent/100)`. Фильтр инструмента и включаемый эффект Filter — разные узлы, оба могут влиять на звук. Вибрато некоторых пресетов задано собственными параметрами; Modulation добавляет глубину живому каналу. Смена пресета сбрасывает только sound в его исходные значения и modulation, но не весь проект.

## Эффекты

В MCP и JSON используются поля `on`, `a`, `b`. Значение `a` не всегда означает одну и ту же величину; таблица ниже задаёт точную трактовку.

| Ключ | Параметр a | Диапазон a | Параметр b | Диапазон b | По умолчанию |
|---|---|---|---|---|---|
| reverb | Decay, с | 0.3–6 | Mix | 0–0.8 | on, 2.5 / 0.2 |
| delay | Feedback | 0.05–0.75 | Mix | 0–0.8 | off, 0.3 / 0.22 |
| distortion | Drive | 0–0.95 | Mix | 0–0.8 | off, 0.25 / 0.25 |
| chorus | Rate, Hz | 0.1–8 | Mix | 0–1 | off, 1.7 / 0.3 |
| phaser | Rate, Hz | 0.1–6 | Mix | 0–1 | off, 0.7 / 0.3 |
| filter | Cutoff, Hz | 100–16000 | Resonance Q | 0.1–12 | off, 4500 / 1.3 |
| tremolo | Rate, Hz | 0.5–14 | Mix | 0–1 | off, 5 / 0.4 |
| compressor | Threshold, dB | −45–0 | Ratio | 1–12 | on, −22 / 3 |

Порядок цепи: Reverb → Delay → Distortion → Chorus → Phaser → Filter → Tremolo → Compressor. Для эффектов с wet выключение задаёт wet=0, а Filter и Compressor исключаются из маршрута. Изменения многих параметров сглаживаются примерно за 30 мс. Время Delay фиксировано музыкальным значением `8n`; `a` меняет обратную связь, а не время задержки. Reverb имеет preDelay 0.015 с; его готовности ожидает аудиодвижок.

После общей цепи находятся Master Gain и Limiter с порогом −1 dB. Метроном идёт непосредственно на Master, обходя общую FX-цепь. Анализаторы берут сигнал после лимитера.

## Музыкальные единицы

- MCP `duration_beats` — четвертные доли; 4 beats при 120 BPM = 2 секунды.
- `start_step`, `duration_steps`, `pattern.melody.duration`, `events.start/duration` — шестнадцатые шаги; при 120 BPM шаг = 0.125 с.
- 1 четверть = 4 шага. Длительность цикла: `length * 60 / bpm / 4` секунд.
- 16 шагов = 1 такт 4/4; 32 шага = 2 такта. Длина не равна числу четвертей.
- Velocity в API — 0…1 с нижними пределами конкретного инструмента; в интерфейсе обычно показывается в процентах.
- `root` — класс высоты 0=C … 9=A … 11=B, а `note` — абсолютная MIDI-нота.

# MCP: подключение и практика

## Что соединяется

Чат вызывает инструменты приватного Site MCP. Worker проверяет личность пользователя и выбранную браузерную сессию. Команды изменения записываются в D1. Открытая веб-студия забирает их, применяет через OrbitControl и отправляет подтверждение. Звук создаётся на устройстве с этой вкладкой.

Веб-студия: `https://orbit-keyboard-studio-29oct.druidbeat.chatgpt.site/`.
MCP и OAuth resource: `https://orbit-keyboard-studio-29oct.druidbeat.chatgpt.site/mcp`.
Плагин: **ORBIT — Music Keyboard Studio**.

При публикации Sites с capability `mcp` создаётся связанный личный плагин. Его нужно подключить через поддерживаемый интерфейс клиента. Не вставляйте случайный bearer token или заголовок `oai-authenticated-user-id` в пользовательские инструкции: в production заголовок обеспечивает доверенная инфраструктура Sites. Репозиторий не содержит отдельной реализации OAuth-сервера или stdio-сервера.

## Перед изменением студии

Вызовите `orbit_list_sessions`. Если сессия одна, session_id можно не передавать, но явное значение надёжнее. Если сессий несколько, остальные команды требуют `session_id`; сервер не выбирает вкладку по её видимости в интерфейсе. `audio_ready=true` означает, что браузер сообщил о запущенном и running аудиоконтексте в последнем снимке.

`orbit_get_state` и `orbit_get_project` читают серверный кэш снимка. Проверяйте `snapshot_age_ms`: это не синхронный запрос к окну в момент чтения. Небольшая задержка между ручным действием и обновлением состояния нормальна.

## Пример: арфа и C–E–G

Сначала получите ID сессии. Затем дождитесь завершения выбора инструмента и только потом играйте аккорд. ID 24 соответствует Concert Harp. В этом примере C4=60, E4=64, G4=67; запрошенные высоты не меняются гаммой.

```json
{"name":"orbit_configure","arguments":{"session_id":"SESSION_ID","instrument_id":24}}
```

```json
{"name":"orbit_play_notes","arguments":{"session_id":"SESSION_ID","notes":[60,64,67],"duration_beats":4,"velocity":0.8,"respect_scale":false}}
```

`SESSION_ID` — заполнитель, замените его реальным значением. `duration_beats` управляет временем до отпускания; струна и Reverb могут звучать после него. `scheduled=true` подтверждает постановку звука в локальное расписание, а не то, что микрофон измерил слышимый результат.

## Пример: тональность, темп, эффекты

```json
{"name":"orbit_configure","arguments":{"bpm":110,"root":0,"scale":"major","instrument_id":24,"sound":{"cutoff":8500,"pan":0},"fx":{"reverb":{"on":true,"a":3,"b":0.28}}}}
```

Это частичное обновление. Неуказанные параметры сохраняются, кроме sound при действительной смене инструмента: сначала применяются стандартные значения нового пресета, затем переданные поля sound. Повторный выбор уже выбранного ID не сбрасывает изменённый sound.

## Пример: собственный паттерн

```json
{"name":"orbit_set_pattern","arguments":{"length":16,"replace":true,"melody":[{"step":0,"note":60,"duration_steps":2},{"step":4,"note":64,"duration_steps":2},{"step":8,"note":67,"duration_steps":2},{"step":12,"note":64,"duration_steps":2}],"drums":[{"drum":"kick","steps":[0,4,8,12]},{"drum":"snare","steps":[4,12]},{"drum":"hat","steps":[0,2,4,6,8,10,12,14]}]}}
```

`replace=true` очищает строки секвенсора перед применением. Piano Roll остаётся отдельной партией; при необходимости очистите его через `orbit_edit_notes` с `replace=true` и `notes:[]`. Для запуска вызовите `orbit_transport` с `action:"play"` после Start Audio.

При `replace=false` мелодические шаги обновляются выборочно. Переданная барабанная строка всё равно полностью заменяет набор активных шагов именно этой строки: это не операция «добавить несколько ударов».

## Пример: Piano Roll и экспорт

```json
{"name":"orbit_edit_notes","arguments":{"replace":true,"notes":[{"note":60,"start_step":0,"duration_steps":4,"velocity":0.75},{"note":64,"start_step":4,"duration_steps":4},{"note":67,"start_step":8,"duration_steps":8}]}}
```

```json
{"name":"orbit_export","arguments":{"format":"wav"}}
```

Экспорт инициирует скачивание в браузере студии, не создаёт файл автоматически в рабочем каталоге агента. WAV останавливает транспорт и требует готового аудиоконтекста. JSON/MIDI могут экспортироваться без запуска звука. Полный JSON со сэмплами экспортируйте именно через `orbit_export format=json`, а не копированием `orbit_get_project`.

## Подтверждение и pending

```json
{"command_id":"COMMAND_ID","status":"pending","expires_at":1234567890000}
```

Такой ответ означает, что команда поставлена в очередь, но Worker не дождался её ack за короткое окно ожидания. Не повторяйте тот же play/trigger/export наугад. Сначала вызовите:

```json
{"name":"orbit_command_status","arguments":{"command_id":"COMMAND_ID"}}
```

| status | Значение | Следующее действие |
|---|---|---|
| pending | Выполнение/подтверждение ещё не известно | Проверить статус позже; не дублировать звучание |
| done | Браузер подтвердил успех | Использовать value; следующая зависимая команда допустима |
| error | Браузер сообщил ошибку | Прочитать error, устранить причину |
| expired | Время доставки истекло | Сначала выяснить состояние вкладки; затем при необходимости создать новую команду |

При обрыве ack браузер хранит результат последних 128 command_id и при повторной доставке отправляет его без повторного исполнения. Кэш находится в памяти вкладки. Это не безусловная гарантия exactly-once после падения или перезагрузки браузера. Состояние expired означает, что очередь больше не доставляет эту команду; оно не доказывает, что команда никогда не начинала выполняться до потери подтверждения.

## Запись через MCP

`orbit_transport record_start` включает запись и транспорт. `orbit_play_notes` добавляет события в записываемую партию с длительностью в шагах `beats*4`; `record_stop` завершает запись. Ударные и sample-пэды также могут создавать события. Сохранение записью не заменяет экспорт проекта.

## Безопасная музыкальная последовательность

Сначала проверьте сессию и состояние. Для потенциально заменяющих действий получите `orbit_get_project` или сделайте полный JSON-экспорт, если нужен откат со сэмплами. Затем выполняйте зависимые изменения последовательно, ожидая ack. Для ровного ритма задайте паттерн и запустите транспорт: интервалы между отдельными сетевыми MCP-вызовами не подходят для точного музыкального тайминга.

## Локальный API в HTML

В странице доступен `window.OrbitControl`. Это прямой JavaScript API в том же браузере, а не удалённый MCP endpoint. Его `snapshot()` возвращает `{project,state}`, `invoke(name,args)` выполняет поддерживаемую браузерную команду с той же валидацией полей.

```javascript
await window.OrbitControl.invoke('orbit_configure', {instrument_id:24});
// Сначала вручную нажмите Start Audio.
await window.OrbitControl.invoke('orbit_play_notes', {
  notes:[60,64,67], duration_beats:4, velocity:0.8
});
const snapshot = window.OrbitControl.snapshot();
```

Локальный invoke не поддерживает серверные операции списка сессий и статуса команды, не требует session_id, не создаёт D1 command_id и возвращает значение непосредственно. `orbit_list_instruments` локально возвращает массив каталога, тогда как удалённая версия оборачивает его в объект `instruments`. `OrbitMcpBridge` — внутренний модульный объект, не публичный `window` API.

Определения извлечены из `mcp/protocol.js` сохранённой версии. Полные исходные JSON Schema и annotations находятся в `reference/mcp-tools.json`. ## Что означают annotations

ReadOnlyHint описывает отсутствие изменения музыкального состояния. DestructiveHint=true у load_project указывает на замену всей сессии. IdempotentHint — подсказка клиенту, а не гарантия доставки exactly-once: configure и set_pattern помечены идемпотентными, но создают историю/зависят от текущего состояния и могут повторно обновлять UI. Для pending всё равно проверяйте command_status. OpenWorldHint=false означает, что заявленные операции действуют внутри студии; экспорт инициирует локальную браузерную загрузку.

## Общее представление успешного изменения

```json
{"command_id":"COMMAND_ID","session_id":"SESSION_ID","status":"done","ok":true,"value":{"scheduled":true}}
```

У конкретного value форма зависит от инструмента. Для error используются status=error, ok=false и error; при expired отдельного ok может не быть. Сервер помечает такие tool results isError=true. Для get_state/get_project/list/status результат не оборачивается в новый queued command.

# Проекты, хранение и экспорт

## Где находятся данные

| Место | Содержимое | Что учитывать |
|---|---|---|
| Память вкладки | Текущий state, декодированные сэмплы, синтезаторы, Undo/Redo, кэш ack | Теряется при закрытии или перезагрузке |
| localStorage `orbit-studio-v1` | Снимок проекта без sample.data | Локален для браузера/источника; это не полный аудиоархив |
| localStorage `orbit-favorites-v1` | Массив избранных instrument ID | Отдельная настройка, отсутствует в обычном JSON-проекте |
| JSON скачанный через Save/export | Полный state, в том числе встроенные sample.data | Основной переносимый формат сохранения |
| D1 snapshot | Последний присланный project без аудио и краткий state | Кэш для MCP, не резервная копия проекта |
| D1 commands | Аргументы и результаты удалённых команд | Загруженный через MCP project может содержать переданное пользователем аудио |

Обычно аудиобайты остаются в браузере: периодические снимки и `orbit_get_project` их исключают. Если вручную передать `project.samples[].data` в `orbit_load_project`, эти байты входят в аргументы команды и сохраняются в серверной очереди до её очистки. Поэтому утверждение «MCP никогда не передаёт аудио» было бы неверным.

## Формат JSON version 1

Полный корректный стартовый файл находится в `reference/default-project.json`; его можно открыть в студии. `reference/project.schema.json` описывает форму данных для разработки, но фактические проверки и нормализация реализованы в `ProjectStorage.validate` и дополнительных проверках MCP.

| Поле | Содержание |
|---|---|
| version | Ровно 1 |
| name | Название проекта; стартовое «Новая сессия» |
| bpm | Темп; валидатор ограничивает 40–240 |
| instrument | ID выбранного тембра 0–35 |
| root, scale, scaleLock | Тоника 0–11, ключ гаммы, режим приведения живых нот |
| octave, octaves | Начальная октава 1–6, видимые октавы 2–4 |
| velocity, sustain | Сила новых нот и удержание; snapshot всегда сохраняет sustain=false |
| loop, metronome | Повтор и метроном |
| padMode, chordType | Режим пэдов и тип аккордов |
| length | 16 или 32 активных шага |
| pattern.melody | Внутренний массив из 32 объектов on/note/velocity/duration |
| pattern.drums | Четыре массива до 32 ячеек: Kick, Snare, Hat, Clap |
| events | События записанной партии, максимум 4096 |
| sound | ADSR, cutoff, resonance, volume, pan |
| fx | Восемь объектов эффектов on/a/b |
| arp | on/mode/rate/oct/gate |
| swing, humanize | Ритмические настройки |
| tracks | Четыре объекта vol/mute в порядке UI: инструмент, барабаны, мелодия, мастер |
| samples | Массив слотов сэмплов; пустые слоты null, заполненные name и необязательный data |
| samplePlayback, sampleVolume | one/gate/loop и громкость сэмплов |
| visualMode | wave/spectrum/particles/geometry |
| xyX, xyY | Привязки осей XY |
| gameStats | Накопленные очки, лучшая серия и badges |

Пример одного шага и одного записанного события:

```json
{"on":true,"note":60,"velocity":0.75,"duration":1.5}
```

```json
{"kind":"note","note":60,"start":0,"duration":4,"velocity":0.75}
```

У события `kind` может быть `note`, `drum`, `sample`; отсутствие kind в старых мелодических событиях трактуется как нота. Для drum/sample поле note обозначает индекс пэда, а не высоту MIDI. `start` и `duration` измеряются в шестнадцатых шагах. Не создавайте барабанные события с произвольными MIDI-номерами, ориентируясь на мелодический пример.

Сэмпл:

```json
{"name":"my-hit.wav","data":"data:audio/wav;base64,BASE64_AUDIO"}
```

Это пример формы поля, не готовое аудио. В metadata snapshot остаётся только `{"name":"my-hit.wav"}`. При восстановлении такого проекта после перезагрузки исходного файла уже нет: движок создаёт встроенный fallback, а название само по себе не возвращает пользовательский звук.

## Загрузка и нормализация

Открытие через файловый интерфейс допускает JSON-файл до 100 000 000 байт. Валидатор проверяет обязательные структуры, версию, количество дорожек, гамму, длину, ID тембра и числа. Короткие массивы паттерна дополняются до 32. Часть значений ограничивается диапазонами; импорт не обязан буквально сохранять некорректные числа. Поля FX дополняются стандартными значениями.

MCP дополнительно проверяет sound/fx/arp по схемам инструментов, ограничивает samples до 16, приводит имя к строке длиной до 120, нормализует несколько логических/числовых полей и допускает аудиоданные только с префиксом `data:audio/`. Если metadata-сэмпл имеет то же имя в том же слоте, что и текущий сэмпл с data, MCP-загрузка сохраняет его существующие байты. Иначе `missing_sample_audio` перечисляет названия без аудио.

`orbit_load_project` заменяет state, останавливает транспорт и очищает историю. Его не следует считать полностью атомарной транзакцией: ошибка декодирования или перестройки после присвоения состояния может потребовать ручного восстановления из сохранённого JSON. Файловый импорт и MCP-импорт имеют общую базовую проверку, но дополнительные MCP-ограничения не полностью дублируются файловым импортом.

## JSON, MIDI и WAV

| Формат | Сохраняет | Не сохраняет как воспроизводимое состояние |
|---|---|---|
| JSON | Проект, параметры, паттерн, события, встроенные сэмплы, статистику | Отдельное избранное, Undo/Redo, незавершённые удержания, сам аудиоконтекст |
| MIDI | Ноты секвенсора и записанной партии, ударные, tempo, 4/4, program change | Аудиосэмплы, FX, реальные браузерные тембры, настройки микшера |
| WAV | Итоговый звук одного цикла и рассчитанного хвоста, с тембром, FX, уровнями и загруженными сэмплами | Редактируемые ноты, состояние проекта, последующую живую игру |

MIDI — Standard MIDI File с одним треком, PPQ=480, мелодический канал 0 и барабанный канал 9 (в пользовательской нумерации — 1 и 10). Tempo переводится из BPM в микросекунды на четверть; размер записан 4/4. Ударные преобразуются в General MIDI [36,38,42,39,45,46,76,50] по индексу modulo 8. Инструмент передаёт program из таблицы пресетов. В другой DAW он звучит её собственным GM-тембром. Sample-события в MIDI пропускаются.

WAV рендерится Tone.Offline, стерео, 44100 Hz, PCM 16 bit. Длина музыки: `length*60/bpm/4`, дополнительный хвост: `max(sound.release, включённый reverb.decay) + 0.5` секунды. Рендер останавливает текущий транспорт. При длинном feedback delay вычисленного хвоста может не хватить для полного затухания: это фиксированная формула, не анализ оставшегося сигнала.

WAV собирается из сохранённых событий и шагов, а не записывается с системного выхода. Текущий live-арпеджиатор, не записанные удержания, метроном, Tone.Transport Swing и случайный realtime Humanize не превращаются автоматически в эквивалентную экспортированную партию. Для предсказуемого переноса сохраняйте нужные ноты в паттерне/Piano Roll и сравнивайте результат рендера. MIDI также не запекает FX, swing и humanize.

Экспорт возвращает факт запуска скачивания. Он не может подтвердить, в какую папку браузер сохранил файл или разрешил ли пользователь последующий системный диалог. Исходные имена: `orbit-session.json`, `orbit-session.mid`, `orbit-session.wav`.

## Практика резервного сохранения

Перед закрытием проекта с пользовательскими сэмплами сохраните JSON и убедитесь, что файл появился в загрузках. Для проверки переноса откройте его в отдельной чистой вкладке и прослушайте нужные пэды. Для обмена редактируемым проектом отправляйте JSON, для прослушивания — WAV, для переноса нот в DAW — MIDI. Очистка браузерных данных удаляет localStorage, но не уже скачанные файлы.

# Архитектура, HTTP и хранение

## Компоненты

```text
Чат / MCP-клиент
   │ tools/call через доверенную авторизацию Sites
   ▼
Worker /mcp ─── чтение catalog/state/project/status
   │ изменение
   ▼
D1 orbit_mcp_commands ◄── poll / ack ── Открытая веб-студия
                                        │ OrbitControl.invoke
                                        ▼
                                   Tone.js / Web Audio
                                        │
                                        ▼
                                   Выход устройства
```

Приложение собрано без framework runtime. `web/index.html` содержит UI, музыкальное состояние и движок; `mcp/protocol.js` — определения и валидацию инструментов; `mcp/browser.js` — исполнитель и мост; `worker/server.js` — HTTP, идентификацию, очередь и JSON-RPC. При сборке эти части объединяются с каталогом. Tone.js 14.8.49 включён локальным файлом, в автономном HTML — встроенным скриптом.

## Аудиомаршруты

```text
live + remote → instrument Filter → Vibrato → Pan → канал Инструмент ┐
seq → отдельные Filter → Vibrato → Pan → канал Мелодия               ├→ FX → Master → Limiter → выход
drums + sample Players → канал Drum rack                            ┘
метроном ───────────────────────────────────────────────────────────→ Master
Limiter → Waveform / FFT / Meter → Canvas
```

Массив внутренних аудиоканалов и порядок фейдеров UI различаются: applyTracks использует отображение [0,2,1]. Мелодические события секвенсора и Piano Roll идут в seq, удалённые короткие ноты — в remote, а физические клавиши — в live. Результирующий звук всё равно использует один выбранный пресет.

## Состояние и владельцы нот

`AudioEngine.sources` связывает источник pointer/key/pad с нотой, `owners` хранит набор удерживающих источников на высоту. Отпускание одного источника не выключает ноту, которую продолжает удерживать другой. `deferred` хранит отпускания под Sustain. `panic()` снимает голоса, очищает активные источники и sample Players, сбрасывает pitch. StringSynth поддерживает собственные voice envelopes, cache и dispose.

Sequencer использует Tone.Transport с repeat на шестнадцатых, арпеджиатор — проверку сетки на тридцать вторых. UI-подсветка планируется Tone.Draw, а не управляет звуком через задержки DOM. RecordingManager хранит временные pending-ноты, затем превращает их в события. History хранит JSON снимков pattern/events/length.

## HTTP маршруты

| Метод и путь | Назначение |
|---|---|
| GET/HEAD `/`, `/index.html` | Страница со вставленным MCP-мостом |
| GET/HEAD `/tone.js` | Локальная библиотека Tone |
| GET/HEAD `/Tone.js.LICENSE.txt` | Лицензия библиотеки |
| GET/HEAD `/download/music-keyboard-studio.html` | Самодостаточный HTML как attachment |
| POST `/mcp` | JSON-RPC MCP |
| POST `/api/orbit/connect` | Создать браузерную сессию |
| POST `/api/orbit/poll` | Обновить снимок и получить до 16 команд |
| POST `/api/orbit/ack` | Подтвердить команду и новый снимок |
| POST `/api/orbit/disconnect` | Пометить вкладку отключённой, истечь pending-команды |

JSON API отвечает `Content-Type: application/json`, `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`. Статика получает no-cache. Тела JSON ограничены 524288 байтами; проверяются Content-Length и фактическая UTF-8 длина. Ограничение относится ко всему HTTP-запросу, а не только к вложенному project.

Браузерный API принимает только POST. Если Origin передан, он должен совпадать с origin запроса или каноническим ORBIT origin. Отсутствие Origin само по себе не заменяет проверку личности. Это не общедоступный CORS API для произвольных сайтов.

## connect / poll / ack / disconnect

```json
{"label":"ORBIT · браузер","snapshot":{"project":{},"state":{"audio_ready":false}}}
```

Это форма connect; реальная студия отправляет полный снимок. Ответ содержит `session_id`. Poll принимает `session_id` и новый `snapshot`, отвечает `commands:[{id,tool,arguments}]`. Команды сортируются по created_at и rowid; возвращаются только pending и ещё не истёкшие.

```json
{"session_id":"SESSION_ID","command_id":"COMMAND_ID","result":{"ok":true,"value":{"scheduled":true}},"snapshot":{"project":{},"state":{}}}
```

Ack проверяет пользователя, сессию и команду, затем сохраняет статус done/error, result и snapshot. Повторный ack уже завершённой команды не меняет её результат. Просроченный pending ack получает COMMAND_EXPIRED. Disconnect принимает только session_id, сбрасывает updated_at и expires_at pending-команд. При pagehide браузер пытается отправить disconnect через sendBeacon; доставка beacon не гарантирована.

## D1

| Таблица | Поля |
|---|---|
| orbit_mcp_sessions | id PK, user_id, label, snapshot JSON string, updated_at epoch ms |
| orbit_mcp_commands | id PK, user_id, session_id, tool, arguments JSON string, created_at, expires_at, status, result JSON string/null |

Индексы: sessions(user_id,updated_at) и commands(session_id,user_id,status,created_at). Миграция: `drizzle/0000_orbit_mcp.sql`; журнал миграций хранится в `drizzle/meta/_journal.json`. В manifest D1 binding — строка `DB`. R2 не используется.

Все операции пользователя фильтруются по user_id; владение сессией проверяется до изменения. SQL использует bind-параметры. В этой схеме нет отдельных таблиц песен или проектов: одна активная сессия хранит один последний снимок.

## Очередь, сроки и повторные доставки

| Настройка | Значение |
|---|---|
| Активность сессии | Снимок обновлялся в пределах примерно 90 с |
| Интервал следующего browser poll | 900 мс после завершения предыдущего прохода |
| Тайм-аут browser fetch | 12 с |
| Максимум команд за poll | 16 |
| Лимит живых pending на сессию | 64 |
| TTL play_notes/trigger_pad/transport | 15 с |
| TTL остальных изменений | 90 с |
| Ожидание ack в tools/call | До 12 проверок с паузами 250 мс, плюс время DB |
| Кэш результатов в памяти вкладки | 128 command_id |
| Очистка старых записей | При новом connect: команды с expires_at старше 24 ч и сессии с updated_at старше 24 ч |

Очистка запускается при connect, это не гарантированный фоновый TTL-сервис. Записи могут оставаться дольше 24 часов, если никто не подключается. Поллинг не push/WebSocket; фоновые вкладки и энергосбережение могут задерживать доставку. Сервер хранит команды, но не генерирует звук вместо закрытой вкладки.

## MCP JSON-RPC

Реализованы `server/discover`, `initialize`, `ping`, `tools/list`, `tools/call` и принятие `notifications/*` с HTTP 202. Основная объявленная версия в коде — `2026-07-28`; initialize при другом запросе отвечает fallback `2025-11-25`. Это описание совместимости конкретной реализации, не обещание поддержки всех возможностей будущих стандартов MCP.

```json
{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"orbit_list_instruments","arguments":{}}}
```

```json
{"jsonrpc":"2.0","id":1,"result":{"content":[{"type":"text","text":"{\"instruments\":[]}"}],"isError":false}}
```

Полезная нагрузка ORBIT находится в JSON-строке text и требует ещё одного JSON.parse при использовании низкоуровневого клиента. Ошибки команды обычно возвращаются как result с isError=true, а не HTTP 500. Ошибки JSON-RPC имеют коды −32700/−32600/−32601/−32602. GET /mcp отвечает 405 с Allow: POST. Batch RPC, SSE-streaming, MCP resources и prompts в сервере не реализованы.

## Идентификация и границы доверия

Production Worker доверяет `oai-authenticated-user-id`, который устанавливает Sites. Он не проверяет собственную сессию логина по cookie и не верифицирует самостоятельно подпись bearer token. Без доверенного прокси перед Worker такой заголовок можно подделать; при переносе на другой хостинг orbitUser нужно заменить реальной проверкой личности. Тестовая подстановка личности допустима только в loopback preview.

Схемы инструментов запрещают лишние поля и не содержат eval/execute_script. Это ограничивает команды явным набором операций; не означает, что вся браузерная среда стала изолированным sandbox для недоверенных скриптов. Не добавляйте произвольное исполнение кода как способ управления студией.

Site остаётся с прежней приватной аудиторией. Изменение адреса или развёртывание копии не переносит автоматически аккаунты, OAuth, D1 и права. Endpoint позволяет менять музыкальный проект; не публикуйте секреты в проекте, примерах или документации.

## Команды

В корне распакованных исходников:

```sh
node scripts/build-mcp.mjs
node scripts/validate-mcp-artifact.mjs
node --test tests/mcp.test.mjs
```

Эквивалентные scripts: `npm run build`, `npm test`; установки npm-зависимостей им не требуется. После изменения исходников сначала пересоберите dist, поскольку тесты читают собранный Worker.

## Что делает build

1. Читает web/index.html.
2. Извлекает 36 пресетов и категории из известных участков исходника; проверяет полноту каталога.
3. Заменяет маркер `/* ORBIT_MCP_BRIDGE */` на каталог, protocol и browser bridge.
4. Встраивает HTML, Tone.js и лицензию в Worker вместе с protocol и backend.
5. Копирует hosting.json в dist/.openai.
6. Создаёт build/index.html, build/catalog.json и самодостаточный build/music-keyboard-studio.html.

| Результат | Использование |
|---|---|
| dist/server/index.js | Worker ESM entrypoint для развёртывания |
| dist/.openai/hosting.json | Metadata размещения в deploy archive |
| build/index.html | Веб-страница с внешним локальным tone.js |
| build/catalog.json | Каталог инструментов |
| build/music-keyboard-studio.html | Автономная версия для скачивания |

`build/index.html` сам по себе ожидает соседний tone.js: для простого статического preview используйте standalone или скопируйте библиотеку. Полный HTTP preview Worker автоматически обслуживает /tone.js.

Парсер build использует регулярные выражения и границы `const presets`, `const presetGroups`, `const midiPrograms`. При рефакторинге этих объявлений обновите парсер. Сейчас количество 36 проверяется жёстко. При добавлении инструментов нужно изменить эту проверку, каталог, диапазон ID, тесты и документацию.

## Локальная проверка

Для обычной игры откройте build/music-keyboard-studio.html через file://. Для контроля UI по HTTP можно запустить:


Для полного локального Worker+MCP теста используйте включённый `examples/local-preview.mjs`. Запускайте его из корня исходников, передав абсолютный путь к самому скрипту:

```sh
node /absolute/path/ORBIT-Documentation/examples/local-preview.mjs
```

Он слушает только 127.0.0.1:8765, подключает tests/d1.mjs, создаёт SQLite в памяти и подставляет тестового пользователя `qa-owner`. Данные исчезают при остановке. Не размещайте этот адаптер в production и не меняйте bind на 0.0.0.0: он сознательно не реализует реальную авторизацию.

Пример запроса к локальному preview:

## Публикация через Sites

Это описание рабочего процесса, доступного при наличии плагина Sites у редактора. Нативные tools и их схемы проверяйте в установленной версии плагина; они не являются CLI-командами пакета ORBIT.

1. Получите существующий сайт через get_site и сохраните прежнюю аудиторию. Текущий сайт подтверждался owner-private.
2. Получите временный source repository write credential через create_source_repository_write_credential.
3. Откройте/синхронизируйте checkout source helper до редактирования. Если доступ использует work_proxy, не создавайте собственные token headers.
4. Измените исходники, соберите и выполните подходящие проверки.
5. Запустите source helper для commit/push/package. Передавайте credential через stdin, а не аргументы командной строки или файлы.
6. Передайте точные возвращённые project_id, commit_sha и archive в save_version_and_deploy_private для подтверждённого owner-private сайта. Для иной аудитории применяется соответствующий обычный workflow, без скрытого изменения доступа.
7. Если ответ pending/building/publishing, отслеживайте get_deployment_status до terminal. succeeded подтверждает публикацию. При уже сохранённой версии повторяйте deployment, а не создавайте дубликаты version.
8. Проверьте страницу, MCP и загрузку standalone при необходимости; сохраните source provenance.

Source helper поставляется Sites-плагином. Его путь зависит от установки; не переносите абсолютный путь чужой машины как настройку проекта. Форма запуска:

```sh
node /path/to/sites-plugin/scripts/site-workflow.mjs --project-id EXACT_PROJECT_ID
```

После «Ready for Site workflow JSON on stdin» helper получает объект:

```json
{"credential":"RETURNED_CREDENTIAL_OBJECT","source":"PRIOR_OPEN_RESULT_OBJECT","commands":[],"archivePath":"/absolute/path/deploy.tar.gz"}
```

Два строковых значения в примере — обозначения объектов, не буквальные рабочие данные. В реальном JSON подставляются целые возвращённые объекты. `commands` — массивы аргументов оставшихся проверок/сборок. Для открытия archivePath опускается; при упаковке архив должен соответствовать точному pushed commit. Секреты не сохраняются в документации, ZIP, Git или отчёте.

## Как добавлять возможности

Для нового тембра добавьте preset, включите ID в presetGroups, задайте midiPrograms и при необходимости расширьте synthFactory/StringSynth. Сохраняйте старые ID, чтобы ранее сохранённые проекты открывались корректно. Проверьте C4/A4, полифонию, Sustain, Stop, переключение инструментов, live/seq/remote и offline WAV.

Для новой MCP-команды добавьте строгую inputSchema, описание с единицами и annotations в protocol; обработчик в OrbitControl.invoke; серверное чтение или очередь в worker; TTL по характеру команды; тесты ошибок и повторных доставок. Не добавляйте произвольный JavaScript evaluator. Обновите жёсткие ожидания количества tools в validator и тестах, если количество изменилось.

Изменение DB требует новой миграции и записи журнала; опубликованную миграцию не переписывайте как способ эволюции схемы. Изменение формата проекта требует решения о backward compatibility и версии. Текущее приложение принимает version=1; автоматического универсального мигратора версий нет.

# Диагностика и ограничения

## Если не слышно звук

Проверьте Start Audio/Audio ON и активность вкладки, системный выход и громкость. Убедитесь, что Master и нужный канал не Mute, velocity и sound.volume не слишком низкие, фильтр не закрыт. Для MCP сначала получите список сессий, затем audio_ready. После перезагрузки страницы снова нужен локальный запуск аудио. Закрытая или приостановленная вкладка не может синтезировать звук через Worker.

Запрошенная нота может быть ниже/выше текущего видимого диапазона клавиатуры и при этом звучать. Статус scheduled — подтверждение планирования, а не измерение системного выхода. Если Scale Lock изменяет высоту, для точного прослушивания используйте `orbit_play_notes respect_scale=false` либо выключите Scale Lock для локальной игры.

## Индикатор MCP

| Текст | Значение и действие |
|---|---|
| MCP · веб-версия ↗ | Открыт file://; кнопка открывает веб-студию, удалённое управление файлом не включается |
| MCP · подключение… | Создаётся браузерная сессия |
| MCP ● подключён | Сессия зарегистрирована; audio_ready проверяется отдельно |
| MCP · восстанавливаем связь… | Ошибка сети/тайм-аут; мост продолжает попытки при enabled |
| MCP · войдите в студию | Нет принятой сервером авторизации либо запрос отклонён |
| MCP · переподключить | Сессия не найдена; нажмите кнопку для нового connect |
| MCP ○ отключён | Управление этой вкладкой отключено пользователем |
| MCP · недоступен | Connect не удался; проверьте настоящий hosted origin и сервер |

Статический localhost-сервер не имеет /api/orbit. Для него недоступный MCP нормален. Полный preview из examples обслуживает Worker с тестовой D1.

## Ошибки сервера и протокола

| Код/ошибка | Причина | Действие |
|---|---|---|
| AUTH_REQUIRED | Нет доверенной личности Sites | Войти в студию/переподключить личный плагин |
| STORAGE_UNAVAILABLE | В env нет DB | Проверить manifest, binding и публикацию |
| NO_SESSION | Нет активной веб-вкладки этого пользователя | Открыть веб-студию и дождаться подключения |
| SESSION_REQUIRED | Активных вкладок несколько | Список сессий → явный session_id |
| SESSION_NOT_FOUND | ID не найден или принадлежит другому пользователю | Получить свежий ID своей сессии |
| SESSION_OFFLINE | Снимок устарел примерно на 90 с | Вернуться во вкладку, переподключиться |
| QUEUE_FULL | Уже 64 действующие pending-команды | Проверить состояния, дождаться выполнения |
| COMMAND_NOT_FOUND | Нет такой команды у пользователя | Проверить ID, не использовать UUID другого сеанса |
| COMMAND_EXPIRED | Ack пришёл после срока | Проверить локальный результат; не дублировать вслепую |
| ORIGIN_MISMATCH | Браузерный Origin не соответствует студии | Использовать штатную страницу/правильный origin preview |
| INVALID_JSON | Некорректное тело JSON | Исправить JSON и Content-Type |
| INVALID_ARGUMENT | Ошибка схемы либо обычная ошибка команды без отдельного code | Прочитать точный путь поля и сообщение |
| HTTP 413 | Тело больше 512 KiB | Уменьшить запрос; крупный проект открыть файловым интерфейсом |
| HTTP 415 | Не application/json | Указать корректный Content-Type |
| HTTP 405 на GET /mcp | MCP принимает POST | Использовать MCP-клиент или POST JSON-RPC |

Имена ошибок браузерного исполнителя могут находиться внутри строки error, а не в отдельном code. `AUDIO_NOT_READY` просит Start Audio. `AUDIO_STARTING` означает незавершённый запуск движка. `BUSY` просит дождаться рендера WAV. Ошибки «нет изменений для отмены» или «нота выходит за длину паттерна» исправляются изменением операции, а не повторной отправкой тех же аргументов.

## Сэмплы и проекты

Если после перезагрузки вместо пользовательского сэмпла играет другой звук, проверьте, был ли сохранён JSON с sample.data. Автосохранение и серверный снимок сохраняют только имя. Загрузите исходный аудиофайл заново либо полный ранее скачанный JSON.

Если проект не открывается, проверьте version=1, pattern/events/sound/fx/arp/tracks/samples и допустимую scale. Четыре tracks и четыре drum-строки обязательны. Файл UI ограничен 100 MB в десятичном счёте; один загружаемый аудиофайл — 8 MB. JSON с base64 обычно больше исходного аудиофайла.

Если WAV кажется слишком тихим, проверьте уровни перед экспортом. Если отличается ритм, учтите ограничения swing/humanize и live arp: offline export строится из событий, а не из записанного системного сигнала. Если хвост обрезан, сравните Delay feedback с фиксированной формулой хвоста.

## Интерфейс

Нечитаемый белый список был исправлен через `color-scheme:dark` и явные цвета option/optgroup/checked. Эта правка включена в исходники и standalone данной редакции. Если старая копия всё ещё белая, перезагрузите веб-страницу либо скачайте обновлённый HTML. Системные popup могут по-разному рисоваться браузером/ОС; проверка только закрытого select не заменяет проверку раскрытого меню.

На узких экранах микшер скрывается в выдвижную панель, пэды располагаются в четыре колонки. Клавиатуру можно прокручивать горизонтально. Отсутствие фейдеров слева на телефоне не означает, что микшер удалён.

## Известные границы этой версии

- Один текущий мелодический пресет для live/seq/remote, а не отдельный инструмент на каждую дорожку.
- Нет автоматического облачного сохранения песен, общего редактирования, серверного аудиорендера или воспроизведения без браузера.
- Нет импорта MIDI-файла, аудиозаписи микрофона, Web MIDI input/output, VST/AU-плагинов, полноценного аранжировщика или экспорта stems.
- Сэмплы воспроизводятся как аудиобуферы; нет встроенного редактора срезов/таймстретча/нормализации.
- Последовательные удалённые play_notes не предназначены для точного ритма; используйте паттерн.
- `orbit_play_notes` допускает до 12 нот за вызов и максимум 4 четверти удержания. MIDI 0–127 валиден по схеме, но крайние высоты могут быть практически непригодны конкретной модели струны/синтеза.
- История отмены содержит pattern/events/length, но не все параметры. Загрузка проекта очищает историю.
- Потеря ack и перезагрузка вкладки не дают строгой гарантии exactly-once; память кэша результатов ограничена жизнью страницы.
- Параметры sample-экспорта/воспроизведения записанных loop/gate-событий имеют различия между realtime reschedule и offline render; сложные sample-партии стоит проверять прослушиванием обеих версий.
- Клиентский state/снимок может устаревать; audio_ready не гарантирует, что ОС не отключила звук после последнего poll.
- Автосохранение file:// зависит от политики браузера и места файла; перенос файла не является переносом localStorage.

## Что сообщить при диагностике

Укажите веб-версию или имя standalone, действие, полученный текст ошибки, выбранную сессию, возраст снимка, audio_ready, имя тембра и BPM. Для pending сохраните command_id и результат command_status. Приложите минимальный проект без частных аудиоданных, если они не нужны для воспроизведения ошибки. Не передавайте OAuth-токены или source credentials.
